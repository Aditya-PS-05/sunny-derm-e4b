# Q8 vision projector benchmark

Date: 2026-07-16

## Decision

The Q8_0 vision projector is a technically viable beta candidate. On this
70-image paired benchmark, it preserved schema and safety compliance and did
not show a statistically measurable aggregate quality or latency regression.
It reduces the complete download by only 430,497,376 bytes (6.84%), so further
language-model quantization is still required to approach a 4 GB package.

The production server remains on the F16 projector pending validation on
clinician-labelled phone photos.

## Method

- Hardware: NVIDIA L40S 46 GB.
- Runtime: llama.cpp commit `e3546c7948e3af463d0b401e6421d5a4c2faf565`.
- Language model: the same `e4b-derm-Q4_K_M.gguf` for both variants.
- Projectors: F16 baseline versus Q8_0 candidate.
- Dataset: 70 HAM10000 validation images, 10 from each of seven classes,
  sampled with seed 42.
- References: deterministic Sunny morphology labels generated by
  `generate_labels.py`; these are not clinician labels.
- Request: production six-field prompt, image first, temperature 0, seed 42,
  maximum 1,024 generated tokens.
- Execution: warm F16 and Q8 servers; requests alternated by image.
- Uncertainty: paired bootstrap 95% intervals, 20,000 resamples.

## Quality

| Metric | F16 | Q8 | Q8 - F16 | Paired 95% interval |
|---|---:|---:|---:|---:|
| Format compliance | 100% | 100% | 0 pp | - |
| Safety compliance | 100% | 100% | 0 pp | - |
| Disclaimer present | 100% | 100% | 0 pp | - |
| Symmetry exact | 34.29% | 37.14% | +2.86 pp | [-10.00, +15.71] pp |
| Borders exact | 21.43% | 17.14% | -4.29 pp | [-15.71, +7.14] pp |
| Texture exact | 15.71% | 17.14% | +1.43 pp | [-8.57, +12.86] pp |
| Colour Jaccard | 42.45% | 42.74% | +0.29 pp | [-2.79, +3.33] pp |

Paired wins and losses support the same conclusion:

| Field | F16 only correct | Q8 only correct | Both correct | Both wrong |
|---|---:|---:|---:|---:|
| Symmetry | 9 | 11 | 15 | 35 |
| Borders | 9 | 6 | 6 | 49 |
| Texture | 7 | 8 | 4 | 51 |

For colour agreement, Q8 was better on 7 images, F16 was better on 5, and 58
were tied.

Only 4 of 70 complete outputs were byte-identical, and mean text similarity was
0.516. Small projector changes can move greedy generation onto different
wording paths even when aggregate task quality stays similar. Consumers must
continue parsing the schema rather than depending on exact prose.

## Runtime

| Measure | F16 | Q8 | Change |
|---|---:|---:|---:|
| Mean request time | 4,830 ms | 4,854 ms | +23 ms (+0.48%) |
| Median request time | 4,791 ms | 4,814 ms | +23 ms (+0.49%) |
| P95 request time | 5,881 ms | 5,542 ms | -339 ms (-5.76%) |
| Prompt throughput | 1,769.6 tok/s | 1,762.0 tok/s | -0.43% |
| Generation throughput | 134.93 tok/s | 135.16 tok/s | +0.17% |
| Warm load-to-health | 3.048 s | 3.035 s | -0.013 s |
| Steady GPU memory after benchmark | 4,734 MiB | 4,294 MiB | -440 MiB (-9.3%) |

The paired 95% interval for mean request-time change was -93 to +141 ms, so the
observed 23 ms difference is noise at this sample size. Load timing was a single
warm measurement and should not be treated as a cold-start benchmark.

## Limitations

- This is a quantization-equivalence benchmark, not clinical validation.
- HAM10000 contains dermatoscopic images, while Sunny receives phone photos.
- References are deterministic image-morphology labels, not clinician labels.
- The absolute scores are not directly comparable to the older Transformers
  base-plus-adapter evaluation because this test uses the deployed GGUF and
  llama.cpp server path.
- Phone CPU/GPU/NPU latency, thermals, and memory remain to be measured on
  representative Android hardware.

## Reproduction

The candidate was generated with:

```bash
python convert_hf_to_gguf.py \
  --remote --mmproj --outtype q8_0 \
  --outfile mmproj-e4b-derm-Q8_0.gguf \
  google/gemma-4-E4B-it
```

Raw paired results are in `exports/quantization/benchmark-f16-vs-q8.json` and
the conversion log is in `exports/quantization/convert-q8.log`. The benchmark
runner is `scripts/benchmark_projector_quantization.py`.
